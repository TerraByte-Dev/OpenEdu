Card Scaffold

How to add a card. Copy an existing file in design/authored/ and edit — the boilerplate below is what every card gets for free from the build.

Anatomy

1

Line 1 must be the marker, verbatim: <!-- @dsCard group="Components" -->. The build reads the group from it and throws by filename if it's missing. The title is the last segment of the group path.

2

Everything after line 1 is the body. No <html>, <head> or <body> — the build wraps it. A <style> block in the body is valid and is where card-local layout goes.

3

The app's whole stylesheet is already present, so .btn, .tag, .lcd, .window, .cf-input, .glow-line, .phosphor-glow and every --token just work. Use them.

4

Shared furniture: .ds-lede for the intro paragraph, h2 for section headings, .ds-row for a horizontal group, .ds-grid for a grid, .ds-code for the markup block, .ds-note for a footnote.

5

Fonts default to CORE (Lexend, IBM Plex Mono 400/500, Share Tech Mono) at ~150 KiB per card. To also carry Inter and VT323, make <!-- @dsAssets all --> the second line of the file. Only line 2 is checked — scanning the whole file would mean any card documenting the directive also triggered it. Only the typography card needs it, and it lands at 236 KiB against a 240 KiB ceiling.

The one that will catch you

Putting data-theme on an element only changes variables from that element down. Properties already resolved on an ancestor do not re-resolve. A themed tile must therefore restate background: var(--bg); color: var(--ink) on itself, or it will show the new accent against the old background. The build re-scopes the derived tokens (--rule, --ink-dim, --phosphor-faint…) onto every [data-theme] element so those stay correct — but the two properties above are yours.

Tokens, never literals

Do

color: var(--phosphor);
background: var(--panel);
border: 1px solid var(--rule);
background: rgb(var(--phosphor-rgb) / .18);
box-shadow: 0 0 8px var(--phosphor-faint);

Don't

color: #00C6FF;
background: #020409;
border: 1px solid #123;
background: rgba(0,198,255,.18);
box-shadow: 0 4px 12px rgba(0,0,0,.4);

The left column survives all eleven themes. The right column is cyan forever, and the last line is a drop shadow, which this system doesn't have — depth is glow.

Skeleton

<!-- @dsCard group="Components" -->
<style>
  .thing { border: 1px solid var(--rule); border-radius: 12px; background: var(--panel); }
</style>

<h1>Thing</h1>
<p class="ds-lede">What it is and when to reach for it.</p>

<h2>Variants</h2>
<div class="ds-row">
  <div class="thing">…</div>
</div>

<h2>Markup</h2>
<pre class="ds-code">&lt;div class="thing"&gt;…</pre>

Two dead tokens are deliberately excluded from every card and should not appear in new ones: --rule-dim and --rule-w, both zero-use in the app. Leaving them out keeps them from being generated with.
