What it buys on dev is **two items**, `h-xl-hi01` and `h-xl-ar01`, both a native-script spelling of a
note's name that fell below the retrieval floor. Both go from 0/3 to 3/3 on both models. At item
level that is 2 discordant items, both in L2's favour, on e2b: exact McNemar p = 0.5. On qwen a third
item, `h-xl-am03`, went the other way (majority pass 2/3 → 1/3), but its hits were identical in both
arms, so its reply request was too; that flip is sampling (qwen: 2 vs 1, p = 1.0). The retrieval part
is deterministic (the same hits every repeat), but n is 2 items. Do not read more into it than that.

### What the glosses looked like

The gloss is often wrong about the made-up name and retrieval still worked, because the merge keeps
the original question's hits and the rest of the gloss carries the topic:

- e2b, `h-xl-am01` (the Tessik frog in Amharic): "How many eggs does a teacake hold at once?"; qwen:
  "How many eggs does a hen lay at once?". Both still retrieved the frog note (as the original did).
- qwen, `h-xl-hi01`: "…one loaf of bran bread?" and "…bannock bread?"; e2b: "Branock". All three
  retrieved the bread note, which the original question never did.
- qwen, `h-xl-ar03`: "wheat flour" for rye. The answer was still right.

No gloss added a library card on dev. Every glossed row's hits were notes.

## Reloads and the prefix cache

- **Reloads: none.** In all six completed runs the only call with `load_duration` ≥ 1 s is each
  run's first. The gloss call sends the same `num_ctx` as the turn, and Ollama kept the runner.
- **The cache-miss clause was weaker than intended.** The pre-registered rule compared
  `prompt_eval_count`. In Ollama 0.40.15 that count includes tokens served from the cache (every warm
  call reports ~1,400–2,500), so the rule could only catch a gloss call far longer than any English
  turn. It did not fire, but that is a weak check. Reported as written, not replaced.
- **What `prompt_eval_duration` shows (descriptive, chosen after the run):** e2b GPU: the first, cold
  call took 465 ms of prompt evaluation; gloss calls took 86 ms (p50) and the reply after a gloss
  52 ms, against 42 ms for warm English turns. e2b CPU: cold 4,070 ms for 1,566 tokens; gloss calls
  377–474 ms for ~1,450 tokens. A full re-prefill on CPU would cost ~4 s; none was seen. So the gloss
  call does continue the cached prefix. qwen3.5:4b shows little prefix reuse in either arm (warm
  English 374 ms vs cold 750 ms), and its gloss calls (339 ms) are no worse than its normal turns.

## Known limits

- **n is small.** 12 cross-lingual dev items, 6 of them in a non-Latin script. The gain is 2 items.
- **e2b passed the cross-lingual clause at exactly 33/36.** One more miss would have killed it.
- **Latin-script languages are not glossed.** Spanish, French and Swahili already pass 6/6 here.
- **Harmful is a proxy.** No blind rubric pass on the 72 L2 cross-lingual rows.
- **One machine.** CPU timing is the GPU laptop with `num_gpu: 0`, not the reference box.
- **A wrong gloss can add a wrong note.** Candidates from the gloss still face the same floor, and
  none was harmful here, but a mistranslated name could match a different note above the floor.
- **Long conversations are not measured.** The gloss call fits the history without the grounding
  block; if the block then pushes out one more history message, the reply's prefix diverges there.
  Every eval turn here is single-turn.
