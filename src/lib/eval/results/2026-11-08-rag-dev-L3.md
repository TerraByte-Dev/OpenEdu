## The gate

`src/lib/kernel/entityGate.ts` (branch `feat/l3-entity-gate` at `e12c694`, not on master), called from `ground.ts` on the candidates before `selectHits`. A note
is dropped when the question names a distinctive entity the note does not contain and the note names
one the question does not. Distinctive = a Latin capital outside a sentence start, a content word, and
not in the bundled library's vocabulary (4,064 words). Off for questions that do not read as English,
Title Case and ALL CAPS questions, and without a library vocabulary. Library cards are never dropped.
The gate reads the student's words, never L2's gloss. Lowercase entities are not handled.

`m2` asks "What temperature does the Verrin solution need, and how much rye flour per loaf?". It names
one note's entity and only describes the other, so the gate reads the bread note as a different thing.
That is a design flaw any multi-entity question can hit, not a fixture quirk.

## Known limits

- One machine, GPU only; CPU savings are an estimate from token counts.
- No blind rubric. The harm columns are a proxy that misses inventions (see `h-nm19`).
- The gate design was written after reading the v1 dev and test items (which are dev), and its gold
  definition missed multi-hop second notes; the unit test (`entity-gate.test.ts`) pins that finding.
- e2b's real-world set is small (28 items) and the rule's +4 rows sit inside the sampling swing seen on
  untouched items here (±2 per item).
