# RAG grounding eval — gemma4:e4b — 2026-07-26

The measurement behind the Phase 1 falsification condition (#90). Committed so the number is a
record rather than a memory, and so the next run has something to regress against.

## Configuration

| | |
|---|---|
| Model | `gemma4:e4b` via Ollama (tier `small` by name-override) |
| Embedder | `nomic-embed-text`, 768-dim |
| Context | 4096 (`num_ctx`, from `DEFAULT_CONTEXT_TOKENS`; model reports 131072 available) |
| Hardware | RTX 3070 laptop / Ryzen 7 5000-series / Windows 11 |
| Fixture | 12 nonce-fact notes, 20 questions, 3 repeats × 2 mechanisms = 120 turns |
| Commit | `feat/90-grounding-stage` @ the fix for the integrity-check false positive |

## Result

| Mechanism | positives | negatives | multi-hop | Spanish |
|---|---|---|---|---|
| **`always`** (grounding stage) | **36/36** | **12/12** | **6/6** | **6/6** |
| `off` (tool-only) | 6/36 | 12/12 | 0/6 | 0/6 |

**Bar: ≥80% positives AND zero fabricated citations. Result: 100% / zero. MET.**

The A/B clause is also satisfied — the pre-committed condition said *"if tool-only is not measurably
worse, this design is wrong."* Tool-only scored **17%** on positives against 100%, and **0/6** on both
multi-hop and Spanish. The mechanism, not the model, was the constraint.

## What the negatives actually proved

Worth spelling out, because "12/12" is only meaningful if retrieval fired:

| | retrieval | outcome |
|---|---|---|
| n1 — boiling point of ethanol | 3 hits, top 0.61 | retrieved, correctly not claimed |
| n2 — who wrote Hamlet | 6 candidates, top 0.39 → **below floor** | correctly retrieved nothing |
| n3 — area of a circle | 1 hit (Library: Unit Circle), 0.50 | retrieved, correctly not claimed |
| n4 — tallest mountain | 3 hits, top 0.54 | retrieved, correctly not claimed |

Three of four put real passages in front of the model and it declined to attribute its answer to
them. That is the fabrication test doing its job, not passing by absence.

## Caveats — read these before quoting 100%

1. **Retrieval is deterministic, so 3 repeats measured generation variance only.** The `[ground]`
   lines are byte-identical across all three repeats — same hits, same scores, same token counts.
   Same corpus + same embedder = same ranking, every time. So this is 36 independent *generations*
   over 12 fixed retrievals, not 36 independent retrievals. It says nothing about how ranking varies.
2. **The fixture is favourable and is meant to be.** One distinctive value per short note, 12 notes,
   top-3 of a tiny corpus. It was built to answer "does the mechanism work at all", which was the
   stated win condition — not "is retrieval quality solved". A real vault is larger, messier, and has
   overlapping topics. Expect this number to fall on real data; that is not a regression, it is a
   harder question.
3. **GPU, not the target hardware.** Per Q7, everything here ran on an RTX 3070. This isolates model
   capability from hardware speed — the right variable to test first — but it is not evidence about
   a CPU-only machine.
4. **Not run against a cloud model yet.** The design claims to improve capable models too. Unproven.

## Reproduce

```js
await window.__runRagEval({ repeats: 3 })
```

Runs both mechanisms and prints the bar. Refuses to start if another run is in flight, and aborts if
the fixture vault returns zero note candidates — both guards exist because the first attempt at this
measurement raced itself and produced a confident, wrong 36%.
